# 要項チェック（youkou-check）

ハッカソン・奨学金・補助金・コンテストの**要項**と、自分の**提出物**（申請書・見積書などの書類、GitHub リポジトリ、作品の概要など）を突き合わせて、

- 満たしていない条件
- 出し漏れ・書き漏れ
- 本人が確かめるしかない条件

を、**要項の該当箇所の引用つき**で返す道具です。出すかどうか、直すかどうかを決めるのは使う人です。

> 補助金の公募要領は数十ページあり、条件があちこちに散らばっています。「見積書の日付が古かった」「対象外の経費が入っていた」「添付書類が1つ足りなかった」といった不備で、中身を読まれる前に落とされることがあります。この道具は、そうした見落としを提出の前に見つけるためのものです。

## 動かし方

必要なもの：Node.js 22 以上、git、Anthropic の API キー

```sh
git clone https://github.com/ryuik-on/youkou-check.git
cd youkou-check
npm install
cp .env.example .env      # .env に API キーを書く
npm start                 # → http://127.0.0.1:3939 を開く
```

1. 「見本：補助金」を押すと、架空の補助金の公募要領と、わざと不備を入れた申請書類（PDF 5つ）が入ります。「見本：ハッカソン」は、架空のハッカソンの要項と、不備を入れた見本のリポジトリです
2. 「突き合わせる」を押します（1回あたり約2分、API の料金は約 $0.4）
3. 条件ごとに、要項の引用と提出物の根拠が並んで出ます。自分で確かめたものに「自分で確かめた」の印を付けます
4. 「確かめることの一覧をコピー」で、残っている作業を Markdown で書き出せます

自分の提出物を調べるときは、要項を貼り付けるか PDF で読み込み、提出書類（PDF・テキスト）を追加してください。ハッカソンなどの作品は、GitHub の URL か手元のフォルダも入れられます。

コマンドからも使えます。

```sh
node --env-file=.env cli.mjs extract 要項.md                     # 条件の一覧だけ
node --env-file=.env cli.mjs check 要領.pdf 申請書.pdf 見積書.pdf  # 書類と突き合わせ
node --env-file=.env cli.mjs check 要項.md ~/Projects/作品        # リポジトリと突き合わせ
```

## 仕組み

| 段階 | 誰がするか | 何をするか |
|---|---|---|
| 1. 条件の取り出し | Claude | 要項の文章から条件を一つずつ取り出し、原文の引用、種類、守らないとどうなるか（失格・減点・お願い）を付ける。どちらとも読める書き方は「主催者に聞いた方がよいこと」に分ける |
| 2. 引用の照合 | プログラム | Claude が出した引用が、要項の原文にそのまま含まれているかを確かめる。見つからなければ画面に「⚠ 見つかりません」と出す |
| 3. 事実の収集 | プログラム | PDF からの文字の取り出し、書類ごとのページ数・字数、点検した日時、コミットの日時、履歴の中の API キー（消したものも含む）、LICENSE、README、公開かどうか（GitHub の API）、動画の長さ、概要の文字数 |
| 4. 日付の比較 | プログラム | 開発期間より前・締切より後のコミットを数える |
| 5. 突き合わせ | Claude | 条件ごとに「満たしている／満たしていない／判定できません／本人が確かめる」と、提出物側の根拠、直し方を返す |
| 6. 根拠の照合 | プログラム | 提出物側の根拠も、README やファイルにそのまま含まれているかを確かめる |

Claude には、言葉を読む仕事（条件の取り出しと突き合わせ）だけを任せています。日付の比較や鍵の検出のように、プログラムで確実に確かめられることはプログラムでします。Claude が出した引用と根拠は、すべてプログラムで原文と照らし合わせてから画面に出します。

使っているモデルは `claude-opus-5-5`（adaptive thinking、構造化出力）です。

## 限界

- **判定は間違えることがあります。** 最後は自分の目で要項を読んでください。画面の「自分で確かめた」はそのためにあります
- 参加資格（在籍・年齢・居住地など）や、提出フォームに書く内容の多くは、プログラムからは確かめられません。「本人が確かめる」と出します
- 動画は中身を見ていません。長さだけを使います
- 要項の文章・README・ファイルの中身は Anthropic の API に送られます。API キーなどの秘密の値そのものは送りません（見つかった場所だけを送ります）
- 手元（127.0.0.1）でだけ動きます。Web には置いていません

## 他人のリポジトリを調べるときの安全対策

- リポジトリの中の設定で git が外部のプログラムを動かさないようにしています（hooks・fsmonitor・外部 diff などを無効化）
- シンボリックリンクやサブモジュールの先は読みません
- 手元のサーバーは、`127.0.0.1` と `localhost` 宛ての依頼しか受け付けません

## 見本について

`examples/` の要項・要領・申請書類は、動作を見せるために作った**架空の大会・制度・事業者**のものです（`examples/hojokin/src` の HTML から `build.sh` で PDF を作っています）。実在の大会・団体とは関係ありません。見本の提出物に入っている API キーは、形だけ似せた偽物です。
